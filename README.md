# 存档港 SaveHarbor 0.2

Windows 游戏存档管理工具。支持本地建档、备份恢复、文件夹存档库，以及自行配置应用凭据的百度网盘 API 后端。0.2 已实现设备码扫码授权、授权码兑换、Token 刷新、分片上传和版本拉取；自动测试使用模拟百度接口，**尚未使用真实开发者应用验证授权、权限与传输速度**。

此仓库包含源码、构建脚本和验证记录。可执行程序、机器路径预览图、真实游戏存档与凭据不提交到 Git。初次从仓库获取源码后，在 Windows PowerShell 中执行 `./build.ps1` 生成 `SaveHarbor.exe`。

## 启动

解压整个文件夹，双击 `SaveHarbor.exe`。保留同目录的 `SaveHarbor.exe.config`。

升级时先从系统托盘退出 0.1，再启动 0.2。同一数据目录同时只能运行一个实例。已有游戏档案和本地备份沿用 `%LOCALAPPDATA%\SaveHarbor`。

当前可执行文件使用本机已有的 **.NET Framework 4.8 / WPF** 编译，适用于安装该运行时的 Windows。无需安装现代 .NET SDK。`SaveHarbor.csproj` 是现代 .NET 10 / WPF 项目入口，本次没有在现代 SDK 上构建验证。

现代项目中的 `System.Security.Cryptography.ProtectedData` 用于 Windows 当前用户加密；离线 Framework 构建使用系统已有程序集，不下载 NuGet 包。

主窗口关闭后留在系统托盘，右键托盘图标选择“退出程序”才能结束。后台模式可以监测游戏退出。

## 本机建档

1. 添加游戏，输入名称和实际游戏 EXE 的完整路径。请填写真正运行的游戏程序，不要只填会立即退出的启动器。
2. 添加一个或多个存档目录或文件。
3. 软件会把常见位置自动转换成 `{Documents}`、`{LocalAppData}`、`{AppData}` 或 `{UserProfile}` 模板。文档目录从 Windows 获取，包含系统重定向后的位置。
4. 自定义位置使用 `{CustomRoot}`。在“修改模板 / 绑定根目录”中，也可以选择 `{GameRoot}`，分别绑定这台电脑的游戏根目录和相对路径。
5. 关闭游戏后，点击“分析存档”和“创建备份”。分析显示实际文件数、大小和内容变化；备份完成后显示原始与压缩体积。

添加时选择已有目录；在新设备恢复时，目录可以尚不存在，但根目录必须正确绑定。避免选择整个用户目录或整个游戏目录。

## 版本和恢复

每个版本包含 ZIP、逐文件 SHA-256、备份包校验和、来源设备、UTC 时间、父版本和存档位置标识。日期只是时间线展示信息，不用于强制覆盖。

选中版本并恢复时，会先校验内容和路径，检查游戏进程，备份当前文件，然后安装版本中的文件，移除所选存档范围中该版本没有的其他文件。这样可以恢复整个存档状态，而不是混合两个版本。

写入失败时尝试自动回滚原文件；若磁盘或权限问题同时阻止回滚，错误会显示恢复前备份的版本编号。请保留软件数据目录，并在排除占用或权限问题后使用那份备份恢复。

若添加或移除了存档位置，旧版本的位置集合可能与现在不同，软件会阻止恢复。重新绑定现有位置的根目录不改变位置标识，可以正常跨设备恢复。

目录链接、符号链接和重解析点暂不支持；这也可能影响部分云盘按需下载目录。请先使用普通、已完整下载到本机的文件夹测试。

## 游戏退出自动备份

为游戏勾选“游戏退出后自动备份”，保持存档港运行。软件每 3 秒检查一次填写的 EXE 名称，识别进程由运行到退出的变化。退出后的内容与当前版本相同时，不重复创建版本；备份失败最多重试 3 次。

此版本只自动备份到本机，**不会自动发布到文件夹存档库**。进程检查依据文件名，无法区分同名程序；如果游戏使用其他子进程，应填写实际游戏进程的 EXE。

## 文件夹存档库 / 换电脑

文件夹存档库是一种可替换存储后端，支持普通文件夹、移动磁盘、共享目录，以及外部同步工具实际管理的目录。它本身不是网盘账号连接。

1. 两台设备都启动存档港。
2. 设备 A 设置一个已有文件夹作为存档库，选择本地版本，点击“发布选中版本到存档库”。
3. 把完整存档库通过外部网盘客户端、移动磁盘或共享目录传到设备 B。外部工具是否上传完成需要另行确认，不要把“发布完成”理解为“网盘传输完成”。
4. 设备 B 设置对应文件夹，点击“从存档库拉取”。这一步下载/导入版本，但不会覆盖游戏文件。
5. 编辑导入档案，设置设备 B 的游戏 EXE。常见用户目录模板自动解析；`GameRoot` 和 `CustomRoot` 需要重新绑定。
6. 选择正确的版本并恢复。

游戏目录根路径与 EXE 不写入便携档案。两个设备从同一父版本分别产生的版本都会保留，冲突时手动选择整个版本。当前版本尚无自动冲突提示或自动选择最新云端版本。

同步库和软件数据目录、所选存档目录必须互不重叠。若你的百度网盘客户端没有提供文件夹同步能力，可以手动上传/下载整个存档库，或先使用移动磁盘完成两台电脑测试。

## 软件数据

默认位置：`%LOCALAPPDATA%\SaveHarbor`。

- `settings.json`：本机游戏档案、路径绑定、自动备份开关和存档库位置。
- `versions/<游戏ID>/<版本ID>/manifest.json`：版本清单。
- `versions/<游戏ID>/<版本ID>/save.zip`：存档包。

版本不会自动清理。当前版本的包体积和历史数量会影响磁盘占用；后续再加入保留策略。不要手动编辑 manifest 或改动 ZIP。

## 百度网盘配置和使用

打开左侧“百度网盘配置 / 授权”，填写自己的应用信息。真实应用权限和当前账号权益由百度决定。

| 参数 | 如何填写 |
| --- | --- |
| AppKey / Client ID | 百度网盘开放平台的应用 AppKey，不是 AppID |
| Secret Key | 同一应用的 Secret Key；只在软件中填写 |
| 云端目录 | `/apps/实际应用名称/SaveHarbor`，必须属于该应用获准写入的目录 |
| Scope | 默认 `basic,netdisk`；必须包含 `netdisk` |
| 回调地址 | 默认 `oob`；设备码模式不依赖回调。授权码模式必须与开放平台配置一致 |
| Access / Refresh Token | 可选的高级手动入口；已有有效 Token 时可直接填入 |
| 每次请求超时 | 默认 120 秒，可填 10–600 秒 |
| 单包大小上限 | 默认 4096 MB，可填 1–131072 MB；百度接口自身限制仍然适用 |

操作步骤：

1. 填写应用信息与实际云端目录，勾选“使用百度网盘作为存档库”。
2. 点击“扫码授权”，扫描软件显示的二维码；二维码无法加载时，可在授权网页输入设备码。软件按服务端要求轮询，最短间隔为 5 秒。
3. 如果应用不支持设备码模式，使用“打开授权码网页”和“兑换授权码”，或手动填写有效 Token。配置页不自动接收回调 URL；HTTPS 回调模式需要你自行获取授权码并核对页面显示的 state。
4. 点击“创建应用内存档目录”，再“测试连接”。创建目录是对当前账号网盘的真实写操作。此步骤用于验证应用目录权限，不等于完整上传下载验收。
5. 点击“保存并应用”。配置页中的应用信息与授权结果在保存前不写入本机配置文件。
6. 主界面选择本地备份并“发布选中版本到存档库”，此时直接使用百度 API 上传。软件显示分片进度，并在 ZIP 上传结束后提交版本清单。
7. 另一台 Windows 设备自行配置同一应用、授权同一百度账号、填写相同云端目录，点击“从存档库拉取”，绑定本机路径后再恢复。

拉取只导入本机版本库，不会自动覆盖游戏文件。云端未提交清单的半完成版本会被跳过；取消按钮会终止当前请求。下载后再次进行 SHA-256 和存档清单校验。目录列表支持分页，大文件使用 4 MB 分片。

单份游戏档案或版本清单的元数据上限为 4 MB；超过时会在上传前拒绝，避免产生软件无法拉取的版本。

授权临近过期或接口返回 Token 过期时，有可用 Refresh Token 的情况下会刷新并重试一次。更换 AppKey / Secret Key / Scope，或手动切换 Access Token 时，会清除未更新的旧凭据，避免沿用上一个账号的刷新凭据。

所有配置和凭据保存在 `%LOCALAPPDATA%\SaveHarbor\baidu.settings.enc`，使用 Windows DPAPI 当前用户加密；不加入 Git、不写入云端存档档案。不要把该文件复制给另一台设备作为登录方式，每台设备应独立授权。接口端点固定为百度官方 HTTPS 地址；配置页不允许替换成任意服务器地址。

游戏退出自动备份仍然只保存到本机，发布到百度网盘由用户手动触发。历史保留策略和自动冲突提示尚未实现。

## 百度官方参考

需要先在官方开放平台创建并取得适用的开发者应用，确认当前平台支持的授权方式、文件权限与速率限制：

- 官方入口：https://yun.baidu.com/open/platform
- OAuth 文档：https://openauth.baidu.com/doc/doc.html

- 官方 SDK 接口参考：https://github.com/baidu-netdisk/baidu-drive-sdk-go/tree/main/baidudriver/api

当前模式是用户自行填写自己的开发者应用凭据；程序不会内置共享 Secret Key。已有百度会员不等于第三方 API 必然获得官方客户端的同等下载速度，需要使用真实账号实测。

代码提供 `IStorageProvider`、`FolderStorage` 和 `BaiduStorage`。之后可以继续完善真实账号验收、同步状态判断、冲突界面、传输队列及版本保留策略。

## 源码、构建和验证

本地存档与主界面在 `SaveHarbor.cs`；百度配置、DPAPI、OAuth 和 API 后端在 `Baidu.cs`；模拟百度接口测试在 `BaiduTests.cs`。

本机离线构建：在 PowerShell 中运行 `build.ps1`。脚本调用 Windows 自带 .NET Framework C# 编译器，不下载依赖。

旧程序正在运行、原 EXE 被占用时，可指定一个独立输出目录：`./build.ps1 -OutputFile 'C:\构建目录\SaveHarbor.exe'`。

测试命令（测试目录必须是一个全新的可写目录）：

```powershell
Start-Process .\SaveHarbor.exe -ArgumentList @('--self-test', 'C:\你的测试目录') -Wait
```

通过后，测试目录包含 `PASSED.txt`；失败时包含 `FAILED.txt`。测试全部使用模拟数据，不读取真实游戏存档。覆盖备份恢复、覆盖前备份、额外文件移除、新设备路径绑定、文件夹存档库、双设备分支、损坏包拦截、路径穿越、锁定文件导致失败后的回滚、运行进程拦截、单文件恢复与超过 10 MB 的存档。

百度模拟测试额外覆盖设备码授权等待/成功、参数编码、过期刷新、4 MB 分片、12 MB 上传下载恢复、半完成版本跳过、取消、1001 条目分页、云端损坏包、下载地址限制和凭据隔离。

本地交付包的配置页预览使用空白凭据。自动进程监测、托盘交互和真实游戏兼容性尚需实际设备体验；本次已完成离线界面渲染检查。真实百度授权和 API 传输尚未验收，需要应用信息与实际账号。
